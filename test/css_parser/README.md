# CSS byte oracle

`goldens/` was captured from the C++ parser at `206b4259`, before its Rust port.
The 58 cases contain the external CSS files from all checked-in EPUBs that have
CSS, literal stylesheets from `CssParserTest.cpp`, and generated edge inputs.
`prepare_oracle.py` recreates the inputs when run from that original revision.
It also derives tag/class/id queries and matching ancestor chains from selectors.

Each case contains:

- `00.css`, `01.css`, etc.: stylesheets loaded in filename order.
- `result.txt`: numeric ParseResult and rule count after each file, then the
  first-letter-rule flag.
- `cache.bin.gz`: exact v19 bytes from `saveToCache`, marked partial when needed.
- `queries.tsv`: tab-separated tag, classes, id, and ancestor chain. Ancestors
  are outermost first, separated by `|`; their three fields use `~`.
- `resolved.bin.gz`: 88-byte style records for each query, ordinary then first-letter.
- `inline.txt` and `inline.bin.gz`: declaration inputs and their 88-byte results.

`OracleWire.h` freezes the original wire encoder, including all defined flags.
It does not serialize structure padding. Both the Rust tests and the C++ golden
test compare exact bytes and resolve styles again after loading the cache.
The wire record is **88 bytes**, including its final four defined-flag bytes.

The binary records use deterministic gzip compression (level 9, timestamp 0).
CMake and the Rust host test run `unpack_goldens.py` with Python 3, writing plain
fixtures outside the source tree. Set the `CSS_GOLDEN_DIR` environment variable
for either test to use an existing uncompressed fixture directory instead.

The three cap cases sample queries, never stylesheet inputs or cache records.
For numeric selector identifiers they keep every 64th identifier, the first two
and last two, and four neighbors `[boundary - 2, boundary + 2)` around each
power-of-two boundary from 16 upward and the first rejected index. That index
is 1,500 for rules, 256 for unique styles, and 146 for selector bytes. All case
and extra-class variants of each selected identifier remain, as do generic
nonnumeric queries. Rule-cap queries shrink 4,563 → 165, style-cap 831 → 78,
and selector-cap 603 → 78. The repeated final accepted rule override remains
covered. Non-cap queries and all inline inputs are unchanged; full cache-byte
comparisons still cover every accepted rule, its selector, style and order.
`prepare_oracle.py::sample_queries` defines this selection.

The original full query set and uncompressed outputs are preserved outside Git
at `~/workspace/crosspoint-evidence/riir-round-2026-10/runs/m4-goldens-full/`, with
per-file sizes and SHA-256 hashes in `sha256.json`. The report records its hash.
The sampled outputs are selected from that original oracle, not regenerated by
Rust. Both tests can still verify the full set using `CSS_GOLDEN_DIR`.

To recapture deliberately, build the original C++ implementation with
`CssGoldenTest.cpp` and run:

```sh
CSS_CAPTURE_ORACLE=1 build/test/css_parser/CssParserTest --gtest_filter='CssGoldenTest.*'
# Outputs are uncompressed in the generated CSS_GOLDEN_DIR. Recompress with:
python3 -c 'import gzip,pathlib,sys; p=pathlib.Path(sys.argv[1]); p.with_suffix(".bin.gz").write_bytes(gzip.compress(p.read_bytes(), compresslevel=9, mtime=0))' path/to/cache.bin
```

Ordinary test runs never update expected outputs. Do not recapture from the
replacement implementation to make a failure pass.

`CssAllocationTest` fails every Rust allocation in a 1,500-rule, 256-style parse
and cache load. It checks Partial/LowMemory, clearing, and successful retry, and
rejects every truncation of a small cache plus trailing data. These tests cover
the C ABI using the production Rust archive with a host allocator shim.
