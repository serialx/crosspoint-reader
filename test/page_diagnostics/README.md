# Page and section diagnostics

`PageDiagnostics` exercises the production `Page::fromBytes` and `Page::load`
paths with exact `(level, origin, text)` expectations captured from upstream
`116195b4`. The frozen files cover 28 focused cases and 7,375 field mutations
of all 1,089 pages in the section corpus. Input names and SHA-256 values bind
mutation expectations to the existing immutable section archive. Valid pages
must remain silent; failing the single page allocation must report its error.
`SectionDiagnostics` injects a version mismatch, layout mismatch, visible-LUT
seek failure and visible-LUT read failure through the production Section code.

```sh
cmake -S test -B build/test
cmake --build build/test --target PageDiagnosticProbe SectionDiagnosticProbe -j 6
ctest --test-dir build/test -R '^(PageDiagnostics|SectionDiagnostics)$' --output-on-failure
python3 test/page_diagnostics/run.py build/test/page_diagnostics/PageDiagnosticProbe \
  --baseline /path/to/283256eb-page-probe --reference /path/to/116195b4-page-probe
```

The optional baseline compares acceptance, allocation attempts, requested
bytes, read/seek counts and the ordered I/O hash for every case. The candidate
also rejects any Rust allocation attempt with the host allocator failure injector
set to zero. The reference compares exact ordered logs and acceptance
on valid pages and corruptions. These probes instrument host allocations; they
do not model ESP heap block overhead or hardware failure timing.

To rebuild the upstream reference, run from the repository root after building
`PageDiagnosticProbe`. The following procedure uses macOS host tools; on Linux,
replace `-Wl,-dead_strip` with `-Wl,--gc-sections` and select the host Rust archive.
Keep the exported source and adapted harness outside the repository.

1. Create a scratch directory and export the original page implementations:

   ```sh
   PAGE_REF=$(mktemp -d)
   git archive 116195b4 lib/Epub lib/Serialization lib/Memory lib/Utf8 \
     lib/MiniBidi src/fontIds.h | tar -x -C "$PAGE_REF"
   cp test/page_diagnostics/PageProbe.cpp "$PAGE_REF/PageProbe.cpp"
   cp test/section_golden/stubs/GfxRenderer.h "$PAGE_REF/GfxRenderer.h"
   ```

2. In the scratch `PageProbe.cpp`, replace the conditional call to `Page::load`
   / `Page::fromBytes` with `Page::deserialize(file)`. Remove
   `xp_test_fail_allocation_after(0);` and the check that returns 4 when
   `xp_test_allocation_attempts()` is nonzero. Append
   `void readerFailureDiagnostic(bool) {}`; the reference comparison uses only
   memory/file modes. Keep the allocation counters and output protocol.
3. In the scratch `GfxRenderer.h`, change the relative include of the chapter
   renderer stub to its absolute path in this checkout. Add the public method
   `bool isFontCacheScanning() const { return false; }` required by the old
   text renderer. No drawing occurs during deserialization.
4. Compile the original codecs with the adapted harness and current host stubs:

   ```sh
   c++ -std=c++20 -O2 -ffunction-sections -fdata-sections -Wl,-dead_strip \
     -I"$PAGE_REF" -Itest/page_diagnostics/stubs -Itest/page_codec_diff/stubs \
     -Itest/section_golden/stubs -Itest/chapter_html_slim_parser/stubs \
     -I"$PAGE_REF/lib/Epub" -I"$PAGE_REF/lib/Serialization" \
     -Ilib -Ilib/Memory -Ilib/EpdFont -Ilib/Utf8 -Ilib/MiniBidi \
     -Ilib/GfxRenderer -Ilib/Epub/Epub/css -Irust/crates/xp-ffi/include \
     "$PAGE_REF/PageProbe.cpp" "$PAGE_REF/lib/Epub/Epub/Page.cpp" \
     "$PAGE_REF/lib/Epub/Epub/blocks/TextBlock.cpp" \
     "$PAGE_REF/lib/Epub/Epub/blocks/ImageBlock.cpp" \
     "$PAGE_REF/lib/Epub/Epub/CjkBreaks.cpp" \
     "$PAGE_REF/lib/Epub/Epub/hyphenation/HyphenationCommon.cpp" \
     lib/Utf8/Utf8.cpp lib/MiniBidi/RustBidi.cpp test/cmake/xp_ffi_host.cpp \
     build/test/xp-ffi-host-target/aarch64-apple-darwin/release/libxp_ffi.a \
     -o "$PAGE_REF/PageReference"
   python3 test/page_diagnostics/run.py \
     build/test/page_diagnostics/PageDiagnosticProbe \
     --reference "$PAGE_REF/PageReference"
   ```

The reference uses the original `Page::deserialize`, TextBlock and ImageBlock
codecs. The current UTF-8/Bidi adapters only satisfy the linked rendering helpers;
this procedure does not replace the legacy decoder or copy it into firmware.

The focused wire fixtures are generated by `cases.py`. Capture with that script
and the frozen reference executable, never the candidate. Mutation fixtures
are generated by `run.py::mutations`; their frozen expectations must likewise
come from the reference. Do not regenerate either golden to hide a mismatch.

These focused mutations avoid unchecked legacy short scalar reads and enormous
legacy string allocations. The separate section mutation oracle covers additional
truncations and offsets; compare against the starting commit as well as its
documented upstream exceptions. Activity-level reader recovery still needs
device testing; these host probes do not exercise the complete activity lifecycle.

`exceptions.json` freezes one approved compound-corruption case. A bad first text
offset and a bad footnote count coexist: the file sizing pass reaches the count
before the full decoder validates the skipped text arena. Memory decoding keeps
the upstream error order. File loading reports the count instead. Both reject;
the existing read and allocation sequences are unchanged. The test accepts only
the explicitly recorded old and new log sequences for these exact bytes.

Seven additional approved exceptions truncate a rule record at lengths 3–9.
The old reader prints zero/partially read metadata; the current minimum-length
and complete-record checks reject earlier. The host probe compiles the actual
initial logging branch from `EpubReaderActivity.cpp` and requires the restored
SD-load error after each failed file load. It also checks metadata-copy failure
separately. This exercises the failure log branch, not the activity's rendering,
retry count, or cache deletion lifecycle. No diagnostic-only reads are added.
