# Reader render-resource ownership

The Rust unit checks exercise the production render-resource storage. They import
the real Rust owner, `Buffer` allocator adapter, application resource ABI and
shared plan/source descriptor declarations.
No synthetic reader session or native Page replaces the resource owner.

Physical allocation callbacks track every requested byte and inject each
reservation failure. Allocations start with nonzero bytes so the tests detect a
loss of the native arrays' value initialization. Physical prewarm callbacks model
a scope that retains its construction address; begin failure, completed scans
and unfinished scans have separate cleanup checks. Repeated scans and frames
must leave no reservations.

With `reader-strips`, the checks cover all four reservation failures, reuse,
adding an image window after text-only preparation, source rejection, plan/window
loans and borrowed scratch. A detach callback re-enters the owner after owned
planes have been freed, while strip storage is still protected. The assertions
keep the exact buffer, prewarm and image-cache cleanup order.

The host prewarm token and display callbacks are named physical substitutes.
These unit tests do not exercise the real font cache, plan encoding, panel pixels,
DMA, target stack or runtime heap placement. The compositions below add real
renderer and replay coverage. The plan's command
pointer uses an opaque pointee in this host crate; its descriptor declaration is
the production source. Target layout probes compile the complete production
crate with the real command type. An unused `Platform` EPUB-leaf pointer is also
opaque here; it is never read or invoked.

The standalone subtree registers `ReaderRenderResources` and
`ReaderRenderResourcesStrips` with CTest, and the full host suite includes both.
Run the Rust checks directly with:

```sh
cargo test --manifest-path test/reader_render_resources/Cargo.toml --locked --offline
cargo test --manifest-path test/reader_render_resources/Cargo.toml --locked --offline --features reader-strips
MIRIFLAGS=-Zmiri-strict-provenance cargo +nightly miri test \
  --manifest-path test/reader_render_resources/Cargo.toml --locked --offline --features reader-strips
```

## Production compositions

The native host suite also registers `ReaderResourceComposition_default/strips`
and `ReaderSessionComposition_default/strips`. They combine the production Rust
owner with the actual Page codec and extracted C++ physical adapters. The session
composition enters and renders through the real session without installing a
legacy Page fixture or RenderCall. Both cover partial allocation failure, source
rejection, cleanup order and callback reentry during detach. The source-width
check passes 758 pixels independently of stride; unsupported stride 95 rejects.

`ReaderRustStripReplay` runs the unchanged `ReaderStripReplay` pixel oracle with
the Rust replay adapter, real font/image paths and actual renderer operations.
It covers retained rows, grayscale, status/polarity and recovery after a cleared
read failure. The native painter is retained under
`test/reader_lifecycle/native_render/` solely for comparison. These checks require
`STRIP_PLAN=ON` and `reader-strips` in `XP_FFI_HOST_FEATURES`.

`ReaderResourceLogParity_default/strips` compares all 144 log cases with the frozen
parent formatter. `ReaderRefreshFrequency_default/strips` compares all 256 raw
settings with the native getter and checks fresh reads and fast-entry max(2).
`ReaderResourceAccess` compiles the actual session accessor in shipping/app-test
and strips off/on configurations: a scoped loan compiles, while using the loan
after dropping ResourceAccess must fail with the borrow-checker diagnostic.

The `.cpp.in` files and `extract_physical.py` are retained test infrastructure.
Each extracted definition, callback initializer and replaced marker must match
exactly once; a changed signature stops generation. `extract_frame.py` supplies
the shared physical renderer fixture and the named frozen parent-frame oracle,
not the production owner. `parent_frame.inc` and `legacy_render_wire.h` remain
only for those historical comparisons; generic host linking provides public
headers alone. Oracle assertions and goldens are not regenerated by extraction.

The parent frame, painter and formatter can be removed later only when an
independent oracle preserves their lifetime, failure, pixel/recovery and text
expectations. Real-owner coverage is a required counterpart, not proof that every
legacy assertion is redundant. Retained Book and child fixtures have separate
migration owners.

These host checks do not establish physical display timing, DMA, target stack,
heap placement or S3 INTERNAL/PSRAM behavior. Target layout, linked stack and
runtime measurements are separate qualification evidence. Hardware verification
must include optional strips, empty/last-row status regions, SD-error recovery,
refresh-setting changes and all four orientations.
